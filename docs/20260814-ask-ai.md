# AI 问答（Ask AI）设计与运维手册

2026-08-14 上线（v0.24.0）。用户在 `/ask/` 就新加坡 AI 提问，DeepSeek 基于全站数据回答并附来源链接，五语可用，多轮对话。

## 架构

```
浏览器 /ask/（vanilla TS + marked/DOMPurify，SSE 客户端，会话仅存页面内存——站内导航保留、刷新即清空）
   │ POST /api/ask  {question, history, lang, sessionId, turnstileToken?}
   ▼
Pages Function functions/api/ask.ts
   ├─ Turnstile 校验（仅当 TURNSTILE_SECRET_KEY 已配置）→ HMAC cookie（1h 免重验）
   ├─ KV 配额：per-IP 每日 30 turns + 全站每日 3000 turns 熔断（仅当 QA_KV 已绑定）
   ├─ KV 首轮问答缓存：key = sha256(问题规范化 + lang + build-commit)，TTL 7 天
   ├─ env.ASSETS 读 /qa-corpus.txt（构建期生成的全站语料 digest，isolate 内存缓存）
   ├─ DeepSeek chat/completions 流式（自动前缀缓存吃掉语料成本）→ SSE 转发
   └─ D1 逐 turn 日志（仅当 QA_DB 已绑定；IP 只存加盐 hash）
```

**检索选型**：不用向量 RAG。语料 digest（当前约 266KB ≈ 7 万 token）作为 system prompt 稳定前缀常驻上下文，DeepSeek 自动前缀缓存把它按 cache-hit 价（$0.0028/M）计费，单 turn 成本 ≈ $0.001。模型对全站内容零检索盲区。依据见 `docs/20260814-stakeholder-iteration-plan.md` 同期的规划讨论与 2026 年检索基准（vector-only 在企业基准 correctness ~33%；长上下文吸收小型稳定语料是行业共识）。

**优雅降级**（关键设计）：所有绑定/secret 都可缺失——没 KV 就不限额不缓存、没 D1 就不记日志、没 DEEPSEEK_API_KEY 时返回 503（或 `QA_MOCK=1` 时返回 mock）。**先合并部署不会破坏任何现有页面**，配好资源后功能自动激活。

## Phase 0：Cloudflare 资源配置（人工，一次性）

> ⚠️ 部署链正处 cutover 半程（见 deploy.yaml 头注释）。**第一步先确认线上 sgai.md 由哪个 Pages 项目服务**（dashboard 看 custom domain 挂在哪个项目上），下面所有绑定都配到那个项目。

```bash
# 1. KV namespace
npx wrangler kv namespace create sgai-qa-kv

# 2. D1 database + 建表
npx wrangler d1 create sgai-qa
npx wrangler d1 execute sgai-qa --remote --file=functions/schema.sql

# 3. Secrets（对准线上项目名）
npx wrangler pages secret put DEEPSEEK_API_KEY --project-name=<线上项目名>
npx wrangler pages secret put QA_HMAC_SECRET --project-name=<线上项目名>   # openssl rand -hex 32
# （可选，启用 Turnstile 时）
npx wrangler pages secret put TURNSTILE_SECRET_KEY --project-name=<线上项目名>
```

4. 在 Pages 项目 dashboard（Settings → Functions → Bindings）把资源绑定到 production：
   - KV namespace binding：名字必须是 **`QA_KV`** → 选 sgai-qa-kv
   - D1 database binding：名字必须是 **`QA_DB`** → 选 sgai-qa
5. （可选）Turnstile：dashboard 创建 widget（invisible），site key 填进 `src/config/ask.ts` 的 `TURNSTILE_SITE_KEY` 并重新部署；secret 见上面第 3 步。**site key 和 secret 必须同时配**，只配一边则该层自动跳过。
6. 部署后 canary：五语各问 1 题；`wrangler d1 execute sgai-qa --remote --command "SELECT count(*), status FROM qa_turns GROUP BY status"` 确认日志入库。


## 运维

```bash
# 用量概览（近 7 天）
npx wrangler d1 execute sgai-qa --remote --command "SELECT substr(ts,1,10) d, count(*) turns, sum(tokens_in) tin, sum(tokens_out) tout, sum(cache='kv') kv_hits FROM qa_turns WHERE ts > datetime('now','-7 days') GROUP BY d ORDER BY d DESC"

# 高频问题（喂回预置问题列表 / 内容选题）
npx wrangler d1 execute sgai-qa --remote --command "SELECT question, count(*) c FROM qa_turns WHERE turn=0 GROUP BY question ORDER BY c DESC LIMIT 30"

# 错误率
npx wrangler d1 execute sgai-qa --remote --command "SELECT status, count(*) FROM qa_turns GROUP BY status"
```

- **调配额**：Pages 项目改 `QA_DAILY_LIMIT` / `QA_GLOBAL_DAILY_LIMIT` 环境变量，重新部署生效。
- **语料超预算**（build 时 warn `[qa-corpus] digest is N bytes`）：按 TRIM ORDER 裁剪 `src/pages/qa-corpus.txt.ts` —— ① debates clip 500→350；② people summary 300→200；③ ecosystem/startups description 250→150；④ 砍 lever project pages 明细列表。改完必须保持确定性排序。
- **成本模型**（DeepSeek V4 Flash，2026-08 价）：前缀 ~70k token cache-hit ≈ $0.0002/turn + 新增输入 ≈ $0.0001 + 输出 ~700 token ≈ $0.0002 → **约 $0.0005/turn**；冷启动 cache-miss 单次 ≈ $0.01。日熔断 3000 turns 把最坏账单锁在 ~$5/天（全部 miss 也 ~$30/天封顶）。

## 页面布局与追问 chips（2026-08-14 迭代）

- **布局**：输入框在上，预置/回流问题栏（「试试这些问题」）固定在输入框下方，**回答后也不隐藏**（每次回答完成客户端重新洗牌，持续给灵感）。对话线程在输入框上方，聊天式阅读顺序不变。
- **会话不落盘**：对话只存客户端模块内存——ClientRouter 站内导航来回保留，刷新/新开 tab 即全新页面（sessionStorage 持久化已移除，旧 key 会被清理）。
- **追问 chips**：prompt rule 8 要求模型在每个答案末尾输出 `===FOLLOWUP===` 一行 + 2–3 个纯文本追问（与答案同语言、逐行）。客户端把 marker 之后的内容剥离出答案（渲染与 history 都不含），以「继续追问」chips 展示在最新答案与输入框之间，点击即发送。流式渲染对半截 marker 做了尾部抑制，不会闪现 `===FOLL`。模型漏出 marker 时静默无 chips，无害降级。KV 首轮缓存存的是含 marker 的原文，回放时同样解析；cache key 含 build-commit，旧缓存自动失效。

## 预置问题：随机化 + 用户问题全自动回流

- **静态池**：[src/config/ask-presets-data.ts](../src/config/ask-presets-data.ts) 每语言 18 条（zh/en/ja/ko 四语手写，zh-tw OpenCC 派生）。/ask/ 每次加载客户端随机抽 6，首页 AskEntry 随机抽 2——静态构建也能每次刷新不同。扩池直接改这个文件（四语同步，rule #5）。
- **动态回流（全自动，无需人工）**：`GET /api/suggest?lang=<lang>` 走 stale-while-revalidate：KV 结果超过 24h 时响应带 `stale:true`，页面 JS 发一个 fire-and-forget 的 `?refresh=1` 请求**同步**跑一轮「D1 挖近 30 天 turn=0 高频问题 → 过滤（长度 8–100、去重、剔除静态池已有）→ DeepSeek 评审」（注意：不能用 `context.waitUntil` 跑这条链——Pages 会静默丢弃，2026-08-14 踩过）。KV 锁保证每语言每 10 分钟最多一轮。`?debug=1` 返回 breadcrumb trace 供排查。进评审前先过文字系统检查（`functions/_lib/lang-script.ts`：en 候选不能含汉字/假名/谚文，zh/zh-tw 必须含汉字，ja 必须含假名，ko 必须含谚文）——D1 的 `lang` 列是页面语言，访客在英文页打中文时只靠评审的“须为该语言”规则挡不住（2026-08-19 漏过一条，英文页推荐栏挂了两周中文）。评审规则：在题、成句、无脏话/广告/隐私/注入、非 ping 试探；**只允许 verbatim 从候选里选**，服务端再做一次候选集合校验，模型改写/编造的一律丢弃。通过的进 KV（每语言最多 6 条），/ask/ 页面加载时拉取并与静态池合并后一起随机。
- 巡检命令：
  ```bash
  npx wrangler kv key get --namespace-id=1098d30fe82744acb6f7e351746c332d "suggest:zh"
  ```
  强制重跑一轮（删 key 后下一个访客触发刷新）：
  ```bash
  npx wrangler kv key delete --namespace-id=1098d30fe82744acb6f7e351746c332d "suggest:zh"
  ```
- 安全边界：用户文本只经 `textContent` 进 DOM（不可能变成 HTML）；评审拒绝即沉默，绝不展示未过审文本；suggest 失败时页面退回纯静态池。

## 已知限制与 v2 backlog

- 语料只到摘要层；辩论/演讲全文（35MB transcript）未入上下文 → v2 加 `read_document(id)` function-calling 工具做 agentic 钻取。
- 首轮缓存只对完全相同的问题生效（规范化后），语义相近不命中——刻意为之，避免错配。
- 访客要“全部名单 / 下载 / CSV”时，prompt rule 9 让模型指向 `/agent/` 与 `/data/*.json`（2026-09-05 加，起因是有人问 “where can i download all 548 names”）。
- ~~D1 FAQ 挖掘手动跑 SQL~~ → 已实现为 /api/suggest 全自动回流（AI 评审，见上节）；内容选题挖掘仍可用运维 SQL。
- 高频问答可沉淀为可索引的 FAQ 静态页（SEO 反哺）。
- 收费/登录提额：`consumeQuota()` 是唯一改动点；D1 数据攒 1–2 个月再决策。
